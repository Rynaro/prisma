# Scout report — Anthropic adapter, 5.x model-family compatibility (Haiku 5.5 / Sonnet 5.5 / Opus 5.5 / Fable 5.1)

> ATLAS scout, standard tier, read-only. 2026-10-16. Base: branch `feat/anthropic-5x-model-compat` @ b441099 (v0.15.0).
> Vendor facts: `docs/_planning/anthropic-5x-compat/research-digest.md` (not re-researched). Paths relative to repo root. OpenAI ADR is `docs/architecture-decision-records/adr-008-gpt6-model-family-compatibility.md`.
> Persisted verbatim by the orchestrator (ATLAS is read-only).

## DECISION_TARGET answer

Every surface below must change (or be consciously left alone) for 5.x support. The Anthropic adapter is far thinner than the OpenAI one was pre-#43, so the gap is larger than "OpenAI minus the endpoint switch":
(1) the default model is retired (`claude-3-5-sonnet-latest` → 404) and nothing in the worker can override it (no `ANTHROPIC_MODEL` env);
(2) the adapter **ignores `request_shaping` entirely** — a per-repo `model: anthropic/claude-sonnet-5-5` in `.github/review-bot.yml` is silently dropped (the orchestrator forwards it, the adapter has 0 references to `request_shaping`/`generation`/`provider_options`), so selecting a 5.x model per repo is impossible today;
(3) `review()` forces `tool_choice` → 400 on Opus 5.5 / Sonnet 5.5 / Fable 5.1, thinking-skip on Haiku 5.5;
(4) `max_tokens` = 4096 with thinking-on-by-default → systematic truncation;
(5) `refusal` stop_reason → misclassified as `schema_validation`; retired-model 404 → retryable-ish `transport` (retried, never surfaced as a notice);
(6) static capabilities (200K window vs 1M on 5.x; `anthropic-approx` margin may under-count on new tokenizers);
(7) no usage telemetry;
(8) docs/env examples/evals have no Anthropic content beyond the API key.

## Findings

**FINDING-001 — `review()` request shape (forced tool).** `packages/providers/anthropic/src/index.ts:239-252` sends `{ model, max_tokens, system, messages, tools:[{name, description, input_schema}], tool_choice:{type:'tool', name:'submit_review_findings'} }`. No `thinking`, no `output_config.effort`, no `strict`, no `betas`. Per digest §6 the forced `tool_choice` is a 400 on Opus 5.5 / Sonnet 5.5 / Fable 5.1 and skips thinking on Haiku 5.5 (same lesson as Prisma's OpenAI empty-review incident). `respond()` (`:320-325`) sends no tools/tool_choice — already 5.x-safe on that axis, but shares the `max_tokens` problem. Confidence: high.

**FINDING-002 — Tool schema contains strict-mode-forbidden keywords.** Built in `packages/shared/src/prompt/review-prompt.ts:75-159` (`buildToolInputSchema(positive_feedback)`, called from `packages/providers/anthropic/src/prompt.ts:51`). It already has `additionalProperties: false` on every object (`:77`, `:103`, `:135`, `:148`) but also `minLength` (`:80`, `:89`, `:95`, `:97`, `:108`, `:113`, `:119`), `maxLength` (`:114`, `:120`), `minimum` (`:81`), `maximum` (`:96`), and `maxItems` (`:158`, highlights). Shared with the OpenAI and Copilot adapters. Digest §6: strict mode rejects numerical/string/complex-array constraints → if `strict: true` is adopted, Anthropic needs a stripped copy of the schema. Zod (`ProviderReviewOutputSchema`) remains authoritative so stripping only loses model hints; OpenAI/Copilot byte-identical schema must stay unchanged. Cheap path: keep constraints out of the Anthropic wire copy via a pure helper (option for FORGE). Confidence: high.

**FINDING-003 — Response parsing is position-independent but `refusal`-blind; `stop_reason` handling narrow.** `extractToolUseInput` (`index.ts:148-172`) scans all blocks by `type` — leading `thinking` blocks are fine. `extractTextContent` (`:119-146`) filters `text` blocks — `respond()` also fine with thinking blocks; throws `schema_validation` if no text remains. Only `stop_reason === 'max_tokens'` is checked (`:264-274`, `:333-343`). `refusal` (HTTP 200, empty/partial content) falls through to "missing tool_use block for tool …" (`:168-171`) or "no text content" (`:140-143`) → `schema_validation` — wrong kind, wrong remedy. With `tool_choice: auto` there will be legitimate no-`tool_use` responses (model answered in text); vendor says check and retry — the adapter has no retry loop. Options for FORGE: one-shot retry / distinct error / treat as empty. `pause_turn` and `fallback` blocks are not handled (low relevance; fallbacks are an opt-in beta). Confidence: high.

**FINDING-004 — `request_shaping` / `generation` / `provider_options` never read by the Anthropic adapter.** `grep request_shaping|generation|provider_options` in `packages/providers/anthropic` → 0 matches; the model is fixed at construction (`index.ts:198`). Contrast OpenAI: `packages/providers/openai/src/index.ts:1318` `const model = input.request_shaping?.model ?? this.model;` + per-request window (`:1332`), output cap (`:1322`, `:1561`), guard (`:1324-1345`), sampling strip (`:620`), passthrough bag (`:538`). Upstream wiring exists: `apps/github-app/src/pipeline/orchestrator.ts:490-544` builds `request_shaping.{model, generation, deterministic_seed, provider_options}`; model is dropped when the slug's provider ≠ active provider (`:499-504`); `provider_options` narrowed to `cfg.provider_options[activeProvider]` (`:518`) — so `provider_options.anthropic` already reaches `input.request_shaping.provider_options`. `hasGeneration` is a hand-maintained 4-field list (`:509-513`). `GenerationSchema` / `ProviderOptionsSchema` are in `packages/shared/src/schemas/config.ts` (fields: `max_output_tokens`, `temperature` 0–2, `top_p` 0–1, `seed`; `provider_options` = `record(string, record(string, unknown))`); `request_shaping` type in `packages/shared/src/schemas/provider.ts` (`provider_options: record(unknown)`). Nothing Anthropic-specific; no enum for `effort`. Hazard: `docs/config-spec.md:70` says "Anthropic and Copilot adapters ignore `generation`" — if the adapter starts forwarding `temperature`/`top_p`, Sonnet 5.5/Haiku 5.5 reject non-default values and the rest of 5.x rejects them entirely (digest §4) → OpenAI D4 sampling-strip analog. `apps/github-app/tests/worker/command-dispatch.test.ts:889-896` uses `anthropic: { thinking: 'enabled' }` as a provider_options echo example (cosmetic, but now a guaranteed-400 example for 5.x). A passthrough bag implies a denylist (OpenAI's `OPENAI_PASSTHROUGH_DENYLIST`, 12 keys) so `model`/`messages`/`tools`/`tool_choice`/`system`/`stream` cannot be overridden; `effort` belongs in `output_config.effort`, not top-level → mapping decision. Confidence: high.

**FINDING-005 — Error mapping.** `packages/providers/anthropic/src/error-mapping.ts:180-222`: network/timeout → `transport` retryable; 401/403 → `auth`; 429 → `rate_limit` + `retry_after_ms`; 5xx → `transport` retryable; **400 → `capability` only if `readErrorType === 'invalid_request_error'` AND message contains `model|unsupported|capability|tool`**, else `transport` non-retryable; everything else (incl. **404**) → `transport` non-retryable. The verbatim 5.x 400 (`tool_choice: type "tool" and "any" are not supported for this model.`) contains "tool" → already maps to `capability` (no remedy, no `param`). `thinking.type.* is not supported…` and `output_config.effort … not supported` map to `capability` only via "model" (they contain "supported" not "unsupported"; the digest's strings do contain "this model" → yes). **404 `not_found_error` (retired model) → `transport` non-retryable**; per `apps/github-app/src/queue/job-queue.ts:94-95` every `transport` is `transient` regardless of `retryable` → retry with backoff, no "Review unavailable (capability)" notice. Distinct gap, highest-value mapping fix. `ProviderError` kinds: `transport | auth | rate_limit | capability | schema_validation | output_truncated | over_budget` (`packages/shared/src/schemas/provider.ts:273-354`), all `.strict()` → a new kind or field is a schema change. `capability` already has optional `param` and `code` (`:307`, `:312`; ADR-008 D11) — not populated by Anthropic. No `refusal` kind. Options: reuse `capability` with `code: 'refusal'`, add a new kind (touches `job-queue.ts` classifyRetry, orchestrator, schema union), or reuse `schema_validation` with a clearer message. The Anthropic SDK error shape is `err.status` + `err.error.error.type` (`readErrorType`, `:75-97`); `param` is not present in Anthropic errors → the OpenAI `param`-keyed remedy table cannot be copied; a message-regex remedy is needed (the `FUNCTION_TOOLS_ON_CHAT_RE` style from `provider-notices.ts:31-32`). Confidence: high.

**FINDING-006 — Worker wiring & env vars.** `apps/github-app/src/worker.ts:183-202`: the Anthropic arm reads only `ANTHROPIC_API_KEY` and `ANTHROPIC_MAX_OUTPUT_TOKENS` (default 4096 via `resolveMaxOutputTokens` `:132`, `:189`); `MAX_TOKENS_PER_PR` → `maxTokensPerCall`. Confidence: high.

## Recommended hand-off

**FORGE decisions:**
1. Replace the forced `tool_choice` with `auto` + prompt instruction naming the tool + presence check; the retry-on-no-tool-call policy (one retry vs distinct error vs treat as empty).
2. `strict: true` or not; if yes, a stripped schema copy for the Anthropic wire (FINDING-002); if no, leave the shared schema untouched.
3. `refusal` handling: `capability` + `code: 'refusal'` (no schema change) vs a new `ProviderError` kind (schema + `job-queue.ts` + orchestrator) vs improved `schema_validation` message.
4. 404 retired-model mapping → `capability` with a remedy naming `claude-sonnet-5-5`/`claude-haiku-5-5`; forced-tool-choice 400 remedy keyed on message (Anthropic has no `param`).
